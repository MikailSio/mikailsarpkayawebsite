L01
Attention Mechanism
Bahdanau attention · Query-Key-Value · Why attention replaced RNNs · 10 min
+

The attention mechanism (Bahdanau et al., 2014) was introduced to solve the Seq2Seq bottleneck: instead of compressing the entire input into a single vector, the decoder can attend to all encoder hidden states at each decoding step, focusing on the most relevant parts.

Core idea: compute a weighted sum of encoder outputs, where weights (attention scores) indicate relevance to the current decoding step. This allows the model to dynamically focus on different parts of the input for each output token.

Attention score: eᵢⱼ = align(sᵢ, hⱼ) — how well input position j matches output position i.
Attention weight: αᵢⱼ = softmax(eᵢⱼ) — normalized to sum to 1.
Context vector: cᵢ = Σ αᵢⱼ · hⱼ — weighted sum of encoder states.

This was the conceptual foundation. The Transformer (Vaswani et al., 2017) took this further by using attention as the only mechanism — removing recurrence entirely.

L02
Self-Attention & Multi-Head Attention
Scaled Dot-Product · Q, K, V projections · Multi-head · Parallelization · 12 min
+

Self-attention lets each token in a sequence attend to every other token (including itself). Unlike RNNs, there's no sequential bottleneck — all positions are processed in parallel.

Each token is projected into three vectors: Query (Q) — what am I looking for? Key (K) — what do I contain? Value (V) — what information do I carry?

Scaled Dot-Product Attention:
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) · V
The √dₖ scaling prevents dot products from growing too large, which would push softmax into regions with tiny gradients.

Multi-Head Attention runs h parallel attention heads with different learned projections, then concatenates and projects the results. This allows the model to attend to information from different representation subspaces — one head might capture syntax, another semantics.

Python — Self-Attention from Scratch
import torch
import torch.nn.functional as F
import math

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
    attn_weights = F.softmax(scores, dim=-1)
    return attn_weights @ V, attn_weights

# Example: seq_len=5, d_model=64
Q = torch.randn(1, 5, 64)
K = torch.randn(1, 5, 64)
V = torch.randn(1, 5, 64)

output, weights = scaled_dot_product_attention(Q, K, V)
print(f"Output: {output.shape}")   # (1, 5, 64)
print(f"Weights: {weights.shape}")  # (1, 5, 5) — attention matrix
L03
Transformer Architecture
Encoder-Decoder · Positional Encoding · Layer Norm · Feed-Forward · 12 min
+

The Transformer (Vaswani et al., 2017) uses only attention — no recurrence, no convolution. The architecture has an encoder stack and decoder stack, each made of identical layers:

Encoder layer: Multi-Head Self-Attention → Add & Norm → Feed-Forward Network → Add & Norm. Decoder layer: Masked Self-Attention → Add & Norm → Cross-Attention (attend to encoder) → Add & Norm → FFN → Add & Norm.

Positional Encoding is added to embeddings because self-attention has no inherent notion of order. The original paper uses sinusoidal functions; modern models often use learned positional embeddings.

Positional Encoding:
PE(pos, 2i) = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
This allows the model to learn relative positions because PE(pos+k) can be represented as a linear function of PE(pos).
Python — Transformer Encoder Layer
import torch.nn as nn

# PyTorch's built-in Transformer encoder
encoder_layer = nn.TransformerEncoderLayer(
    d_model=512,       # embedding dimension
    nhead=8,           # number of attention heads
    dim_feedforward=2048,  # FFN hidden dimension
    dropout=0.1,
    activation='gelu',
    batch_first=True
)

encoder = nn.TransformerEncoder(encoder_layer, num_layers=6)

# Input: (batch=8, seq_len=128, d_model=512)
x = torch.randn(8, 128, 512)
output = encoder(x)
print(f"Output: {output.shape}")  # (8, 128, 512)
L04
Tokenization & Subword Methods
WordPiece · BPE · SentencePiece · Special tokens · 10 min
+

Transformers don't process raw text — they need tokenization. Modern models use subword tokenization that splits rare words into smaller, known pieces while keeping common words intact.

WordPiece (BERT): vocabulary-driven — greedily splits words into longest matching subwords. "tokenization" → ["token", "##ization"]. BPE (GPT): byte-pair encoding — iteratively merges most frequent character pairs. SentencePiece (multilingual models): language-agnostic, treats text as raw bytes.

Special tokens: [CLS] — sentence-level representation (classification), [SEP] — sentence boundary, [PAD] — padding, [MASK] — masked token for MLM pre-training.

Python — HuggingFace Tokenizer
from transformers import AutoTokenizer

# Load BERT tokenizer
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

text = "Transformers revolutionized NLP research."
tokens = tokenizer.tokenize(text)
print(f"Tokens: {tokens}")
# ['transformers', 'revolution', '##ized', 'nl', '##p', 'research', '.']

# Full encoding with special tokens
encoded = tokenizer(text, return_tensors="pt")
print(f"Input IDs: {encoded['input_ids']}")
print(f"Attention Mask: {encoded['attention_mask']}")

# Decode back
decoded = tokenizer.decode(encoded['input_ids'][0])
print(f"Decoded: {decoded}")

# Turkish model
tk_tr = AutoTokenizer.from_pretrained("dbmdz/bert-base-turkish-cased")
print(tk_tr.tokenize("Doğal dil işleme araştırması"))
L05
BERT — Bidirectional Encoder Representations
MLM · NSP · [CLS] token · Pre-training vs Fine-tuning · 12 min
+

BERT (Devlin et al., 2018) is a bidirectional transformer encoder pre-trained on two tasks: Masked Language Modeling (MLM) — randomly mask 15% of tokens and predict them. Next Sentence Prediction (NSP) — predict whether sentence B follows sentence A.

BERT reads the entire sequence bidirectionally (unlike GPT which is left-to-right). The [CLS] token's final hidden state serves as a sentence-level representation for classification tasks.

Key variants: BERT-base: 12 layers, 768 hidden, 12 heads, 110M params. BERT-large: 24 layers, 1024 hidden, 16 heads, 340M params.

Python — Using BERT with HuggingFace
from transformers import AutoModel, AutoTokenizer
import torch

# Load pre-trained BERT
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased")

# Encode text
text = "Natural language processing is fascinating."
inputs = tokenizer(text, return_tensors="pt")

# Forward pass
with torch.no_grad():
    outputs = model(**inputs)

# outputs.last_hidden_state: (1, seq_len, 768)
# outputs.pooler_output:     (1, 768) — [CLS] processed
print(f"Hidden states: {outputs.last_hidden_state.shape}")
print(f"[CLS] vector:  {outputs.pooler_output.shape}")

# For Turkish: use a Turkish BERT
tk_tr = AutoTokenizer.from_pretrained("dbmdz/bert-base-turkish-cased")
model_tr = AutoModel.from_pretrained("dbmdz/bert-base-turkish-cased")
L06
RoBERTa, DistilBERT & Model Variants
Training improvements · Knowledge distillation · Model selection · 10 min
+

RoBERTa (Liu et al., 2019) improves BERT's pre-training by: removing NSP (not helpful), using dynamic masking (different mask each epoch), training longer with more data, and using larger batches. Result: consistently outperforms BERT on all benchmarks.

DistilBERT: 40% smaller, 60% faster than BERT while retaining 97% of its performance. Uses knowledge distillation — the smaller model learns to mimic the larger model's outputs. ALBERT: Factorized embeddings and cross-layer parameter sharing for memory efficiency. ELECTRA: Replaced token detection instead of masked prediction — more sample-efficient pre-training.

Python — Model Comparison
from transformers import AutoModel

models = {
    "BERT-base":      "bert-base-uncased",
    "RoBERTa-base":   "roberta-base",
    "DistilBERT":     "distilbert-base-uncased",
    "Turkish BERT":   "dbmdz/bert-base-turkish-cased",
}

for name, model_name in models.items():
    model = AutoModel.from_pretrained(model_name)
    params = sum(p.numel() for p in model.parameters())
    print(f"{name:18s} → {params/1e6:.1f}M parameters")

# Output:
# BERT-base          → 109.5M parameters
# RoBERTa-base       → 124.6M parameters
# DistilBERT         → 66.4M parameters
# Turkish BERT       → 110.6M parameters
For Turkish NLP: Start with dbmdz/bert-base-turkish-cased or dbmdz/bert-base-turkish-uncased. For multilingual tasks, consider xlm-roberta-base.
L07
Fine-Tuning for Text Classification
HuggingFace Trainer · Dataset loading · Hyperparameters · Evaluation · 12 min
+

Fine-tuning takes a pre-trained model and adapts it to a specific downstream task by training on task-specific labeled data. The pre-trained weights provide a powerful initialization — you typically need much less data and fewer epochs than training from scratch.

Python — Fine-Tuning BERT for Classification
from transformers import (
    AutoTokenizer, AutoModelForSequenceClassification,
    TrainingArguments, Trainer
)
from datasets import load_dataset
import numpy as np
from sklearn.metrics import f1_score, accuracy_score

# 1. Load model & tokenizer
model_name = "dbmdz/bert-base-turkish-cased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name, num_labels=5
)

# 2. Prepare dataset
dataset = load_dataset("csv", data_files={
    "train": "train.csv", "test": "test.csv"
})

def tokenize_fn(examples):
    return tokenizer(
        examples["text"], truncation=True,
        padding="max_length", max_length=256
    )

dataset = dataset.map(tokenize_fn, batched=True)

# 3. Define metrics
def compute_metrics(eval_pred):
    logits, labels = eval_pred
    preds = np.argmax(logits, axis=-1)
    return {
        "accuracy": accuracy_score(labels, preds),
        "f1_macro": f1_score(labels, preds, average="macro")
    }

# 4. Training arguments
args = TrainingArguments(
    output_dir="./results",
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=32,
    learning_rate=2e-5,
    weight_decay=0.01,
    evaluation_strategy="epoch",
    save_strategy="epoch",
    load_best_model_at_end=True,
    metric_for_best_model="f1_macro",
)

# 5. Train
trainer = Trainer(
    model=model, args=args,
    train_dataset=dataset["train"],
    eval_dataset=dataset["test"],
    compute_metrics=compute_metrics,
)
trainer.train()
Common fine-tuning recipe: lr=2e-5, epochs=3-5, batch_size=16-32, warmup=10% of steps, weight_decay=0.01. Monitor validation F1 — stop if it plateaus or drops.
L08
LoRA & Parameter-Efficient Fine-Tuning
Low-Rank Adaptation · QLoRA · PEFT library · When to use LoRA vs full fine-tuning · 10 min
+

LoRA (Hu et al., 2021) freezes the pre-trained model weights and injects small low-rank decomposition matrices into each transformer layer. Instead of updating all 110M+ parameters, you only train ~0.1-1% of them — dramatically reducing memory and compute requirements.

Core idea: weight update ΔW is approximated as the product of two small matrices: ΔW = BA, where B is (d × r) and A is (r × d), with rank r ≪ d (typically r=4,8,16). QLoRA goes further by quantizing the base model to 4-bit precision — enabling fine-tuning of 7B+ models on a single GPU.

Python — LoRA with PEFT
from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForSequenceClassification

# Load base model
model = AutoModelForSequenceClassification.from_pretrained(
    "dbmdz/bert-base-turkish-cased", num_labels=5
)

# Configure LoRA
lora_config = LoraConfig(
    task_type=TaskType.SEQ_CLS,
    r=8,                  # rank (4, 8, 16 common)
    lora_alpha=16,         # scaling factor
    lora_dropout=0.1,
    target_modules=["query", "value"],  # which layers to adapt
)

# Apply LoRA
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Output: trainable params: 294,912 || all params: 108,605,957
# → only 0.27% of parameters are trained!

# Train with HuggingFace Trainer as usual
# trainer = Trainer(model=model, args=args, ...)
# trainer.train()
When to use LoRA: Limited GPU memory, large models (7B+), many domain-specific tasks (train one LoRA adapter per task), or when you want to experiment quickly. When to use full fine-tuning: Small models (BERT-base), ample compute, maximum performance needed, single target task.
