Tutorial · Sequence Modeling

RNN
LSTM

Recurrent architectures for sequential data. From vanilla RNNs to LSTM, BiLSTM, and GRU — the building blocks of sequence modeling before transformers. Still widely used in time series, speech, and as hybrid components in NLP pipelines.

Level: Intermediate
Lessons: 6
Framework: PyTorch
L01
Vanilla RNN & Sequential Processing
Hidden state · Time steps · Vanishing gradient problem · 10 min
+

A Recurrent Neural Network processes sequences one element at a time, maintaining a hidden state that carries information from previous time steps. At each step t, it takes input xₜ and the previous hidden state hₜ₋₁ to produce a new hidden state hₜ.

RNN cell: hₜ = tanh(W_xh · xₜ + W_hh · hₜ₋₁ + b_h) — the same weights W are shared across all time steps (parameter sharing).

The fundamental problem: during backpropagation through time (BPTT), gradients are multiplied at each step. With many steps, gradients either vanish (→ 0, can't learn long-range dependencies) or explode (→ ∞, unstable training). This is why vanilla RNNs struggle with long sequences.

Python — Vanilla RNN in PyTorch
import torch
import torch.nn as nn

# RNN: input_size=128 (embedding), hidden_size=256, 2 layers
rnn = nn.RNN(
    input_size=128,
    hidden_size=256,
    num_layers=2,
    batch_first=True,    # input shape: (batch, seq, features)
    dropout=0.3
)

# Input: batch=32, sequence_length=50, embedding=128
x = torch.randn(32, 50, 128)
h0 = torch.zeros(2, 32, 256)  # initial hidden state

output, h_n = rnn(x, h0)
print(f"Output: {output.shape}")  # (32, 50, 256) — all time steps
print(f"h_n:    {h_n.shape}")     # (2, 32, 256) — last hidden per layer
In practice: Never use vanilla RNN for anything beyond toy examples. Always use LSTM or GRU — they solve the vanishing gradient problem.
L02
LSTM — Long Short-Term Memory
Cell state · Forget gate · Input gate · Output gate · 12 min
+

LSTM (Hochreiter & Schmidhuber, 1997) solves the vanishing gradient problem with a cell state — an information highway that runs through the entire sequence with only linear interactions, allowing gradients to flow unchanged.

Three gates control information flow: The Forget gate (fₜ) decides what to remove from cell state. The Input gate (iₜ) decides what new information to store. The Output gate (oₜ) decides what to output as hidden state.

LSTM equations:
fₜ = σ(W_f · [hₜ₋₁, xₜ] + b_f) — forget gate
iₜ = σ(W_i · [hₜ₋₁, xₜ] + b_i) — input gate
C̃ₜ = tanh(W_C · [hₜ₋₁, xₜ] + b_C) — candidate cell state
Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ C̃ₜ — new cell state
oₜ = σ(W_o · [hₜ₋₁, xₜ] + b_o) — output gate
hₜ = oₜ ⊙ tanh(Cₜ) — hidden state output
Python — LSTM
import torch.nn as nn

# LSTM: same interface as RNN but with cell state
lstm = nn.LSTM(
    input_size=128,
    hidden_size=256,
    num_layers=2,
    batch_first=True,
    dropout=0.3
)

x = torch.randn(32, 50, 128)
h0 = torch.zeros(2, 32, 256)  # hidden state
c0 = torch.zeros(2, 32, 256)  # cell state

output, (h_n, c_n) = lstm(x, (h0, c0))
print(f"Output: {output.shape}")  # (32, 50, 256)
print(f"h_n:    {h_n.shape}")     # (2, 32, 256)
print(f"c_n:    {c_n.shape}")     # (2, 32, 256) — cell state
L03
Bidirectional LSTM (BiLSTM)
Forward + backward pass · Concatenation · Context from both directions · 10 min
+

A standard LSTM only reads left-to-right. A Bidirectional LSTM processes the sequence in both directions and concatenates the outputs. This gives each position context from both past and future tokens — critical for tasks like NER, POS tagging, and text classification.

The output at each time step is the concatenation [h_forward; h_backward], so the hidden dimension doubles. For the final hidden state, both directions' last states are available.

Python — BiLSTM
# Bidirectional LSTM
bilstm = nn.LSTM(
    input_size=128,
    hidden_size=256,
    num_layers=2,
    batch_first=True,
    bidirectional=True,   # ← key parameter
    dropout=0.3
)

x = torch.randn(32, 50, 128)
output, (h_n, c_n) = bilstm(x)

# Output doubles: forward + backward concatenated
print(f"Output: {output.shape}")  # (32, 50, 512) ← 256*2
print(f"h_n:    {h_n.shape}")     # (4, 32, 256) ← 2 layers * 2 dirs

# Extract final hidden state for classification:
# Concatenate last forward + last backward
h_forward  = h_n[-2]   # last layer, forward
h_backward = h_n[-1]   # last layer, backward
h_final = torch.cat([h_forward, h_backward], dim=1)  # (32, 512)
print(f"Classification input: {h_final.shape}")
BiLSTM is still relevant: Even in the transformer era, BiLSTM is used in hybrid architectures (BiLSTM-CRF for NER), as feature extractors for small datasets, and in resource-constrained environments where transformers are too expensive.
L04
GRU — Gated Recurrent Unit
Reset gate · Update gate · Fewer parameters than LSTM · 8 min
+

GRU (Cho et al., 2014) is a simplified version of LSTM with only two gates instead of three: Reset gate (rₜ) controls how much past hidden state to ignore. Update gate (zₜ) controls the balance between old and new information.

GRU merges the cell state and hidden state into a single hidden state — fewer parameters, faster training, often similar performance to LSTM.

Python — GRU
# GRU: no cell state, simpler than LSTM
gru = nn.GRU(
    input_size=128, hidden_size=256,
    num_layers=2, batch_first=True,
    bidirectional=True, dropout=0.3
)

x = torch.randn(32, 50, 128)
output, h_n = gru(x)  # no cell state returned!

print(f"Output: {output.shape}")  # (32, 50, 512)
print(f"h_n:    {h_n.shape}")     # (4, 32, 256)

# Parameter comparison
lstm_params = sum(p.numel() for p in nn.LSTM(128,256,2).parameters())
gru_params  = sum(p.numel() for p in nn.GRU(128,256,2).parameters())
print(f"LSTM params: {lstm_params:,}")
print(f"GRU params:  {gru_params:,}")  # ~25% fewer
LSTM vs GRU: No clear winner. LSTM tends to perform better on longer sequences (separate cell state preserves long-range info). GRU is faster and works well on shorter sequences. Try both and compare on your specific task.
L05
Text Classification with BiLSTM
Embedding → BiLSTM → FC · Padding · pack_padded_sequence · 12 min
+

A complete text classification pipeline: tokenize text → convert to indices → pad sequences → embed → pass through BiLSTM → take final hidden state → classify with a fully-connected layer.

Python — BiLSTM Text Classifier
import torch
import torch.nn as nn

class BiLSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim,
                 num_classes, num_layers=2, dropout=0.3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.lstm = nn.LSTM(
            embed_dim, hidden_dim, num_layers,
            batch_first=True, bidirectional=True,
            dropout=dropout if num_layers > 1 else 0
        )
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(hidden_dim * 2, num_classes)  # *2 for bidir

    def forward(self, x):
        # x: (batch, seq_len) — token indices
        emb = self.dropout(self.embedding(x))     # (batch, seq, embed)
        output, (h_n, _) = self.lstm(emb)

        # Concat last forward + last backward hidden states
        h_fwd = h_n[-2]   # (batch, hidden)
        h_bwd = h_n[-1]   # (batch, hidden)
        hidden = torch.cat([h_fwd, h_bwd], dim=1)

        out = self.dropout(hidden)
        return self.fc(out)

# Create model
model = BiLSTMClassifier(
    vocab_size=30000, embed_dim=128,
    hidden_dim=256, num_classes=5
)
print(f"Parameters: {sum(p.numel() for p in model.parameters()):,}")

# Test forward pass
dummy_input = torch.randint(0, 30000, (16, 100))  # batch=16, seq=100
logits = model(dummy_input)
print(f"Output: {logits.shape}")  # (16, 5)
For variable-length sequences: Use pack_padded_sequence and pad_packed_sequence to avoid computing on padding tokens — this improves both speed and accuracy.
L06
Sequence-to-Sequence (Seq2Seq)
Encoder-Decoder · Teacher forcing · Attention preview · 10 min
+

Seq2Seq (Sutskever et al., 2014) uses an encoder LSTM to compress an input sequence into a fixed-size context vector, then a decoder LSTM generates the output sequence from that vector. Used for machine translation, summarization, and chatbots.

The bottleneck: compressing an entire sentence into a single fixed-size vector loses information for long sequences. This limitation motivated the invention of attention mechanisms — which eventually led to the Transformer architecture.

Python — Seq2Seq Architecture
class Encoder(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True)

    def forward(self, x):
        emb = self.embedding(x)
        output, (hidden, cell) = self.lstm(emb)
        return hidden, cell  # context vector

class Decoder(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, vocab_size)

    def forward(self, x, hidden, cell):
        emb = self.embedding(x.unsqueeze(1))  # (batch, 1, embed)
        output, (hidden, cell) = self.lstm(emb, (hidden, cell))
        prediction = self.fc(output.squeeze(1))
        return prediction, hidden, cell

# The context vector (hidden, cell) from encoder
# initializes the decoder — this is the "bottleneck"
# that attention mechanisms solve (→ Transformers lesson)
Historical context: Seq2Seq + Attention (Bahdanau, 2014) was the dominant approach for machine translation before the Transformer (Vaswani, 2017) replaced it entirely. Understanding Seq2Seq makes the motivation for attention and transformers much clearer.
